## Data Model

### Entity Relationships

<Warning>
  The data model should be normalized to at least third normal form (3NF) to ensure data integrity.
</Warning>

#### Core Entities

<Tabs>
  <Tab title="Users">
    **User Entity Specification**
    
    ```sql
    CREATE TABLE users (
      id UUID PRIMARY KEY,
      email VARCHAR(255) UNIQUE NOT NULL,
      password_hash VARCHAR(255) NOT NULL,
      first_name VARCHAR(100),
      last_name VARCHAR(100),
      role VARCHAR(50) NOT NULL,
      status VARCHAR(20) DEFAULT 'active',
      email_verified BOOLEAN DEFAULT false,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      last_login TIMESTAMP
    );
    ```
    
    **Indexes:**
    - Primary key on `id`
    - Unique index on `email`
    - Index on `role` for filtering
    - Index on `status` for active user queries
  </Tab>
  
  <Tab title="Content">
    **Content Entity Specification**
    
    ```sql
    CREATE TABLE content (
      id UUID PRIMARY KEY,
      title VARCHAR(255) NOT NULL,
      body TEXT,
      author_id UUID REFERENCES users(id),
      category VARCHAR(100),
      status VARCHAR(20) DEFAULT 'draft',
      published_at TIMESTAMP,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      version INTEGER DEFAULT 1
    );
    ```
    
    **Indexes:**
    - Primary key on `id`
    - Foreign key on `author_id`
    - Index on `status` and `published_at`
    - Full-text index on `title` and `body`
  </Tab>
  
  <Tab title="Sessions">
    **Session Entity Specification**
    
    ```sql
    CREATE TABLE sessions (
      id UUID PRIMARY KEY,
      user_id UUID REFERENCES users(id),
      token VARCHAR(500) UNIQUE NOT NULL,
      ip_address VARCHAR(45),
      user_agent TEXT,
      expires_at TIMESTAMP NOT NULL,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    );
    ```
    
    **Indexes:**
    - Primary key on `id`
    - Unique index on `token`
    - Index on `user_id` and `expires_at`
  </Tab>
</Tabs>

## API Specification

### RESTful API Design

<Info>
  The API follows REST principles and uses standard HTTP methods and status codes.
</Info>

#### Authentication Endpoints

<AccordionGroup>
  <Accordion title="POST /api/auth/register">
    **Description:** Register a new user account
    
    **Request Body:**
    ```json
    {
      "email": "user@example.com",
      "password": "SecurePass123!",
      "firstName": "John",
      "lastName": "Doe"
    }
    ```
    
    **Response (201 Created):**
    ```json
    {
      "success": true,
      "data": {
        "id": "uuid",
        "email": "user@example.com",
        "firstName": "John",
        "lastName": "Doe"
      },
      "message": "Registration successful. Please verify your email."
    }
    ```
    
    **Error Responses:**
    - 400: Invalid input data
    - 409: Email already exists
  </Accordion>

  <Accordion title="POST /api/auth/login">
    **Description:** Authenticate user and receive access token
    
    **Request Body:**
    ```json
    {
      "email": "user@example.com",
      "password": "SecurePass123!"
    }
    ```
    
    **Response (200 OK):**
    ```json
    {
      "success": true,
      "data": {
        "token": "jwt.token.here",
        "refreshToken": "refresh.token.here",
        "expiresIn": 3600,
        "user": {
          "id": "uuid",
          "email": "user@example.com",
          "role": "user"
        }
      }
    }
    ```
    
    **Error Responses:**
    - 401: Invalid credentials
    - 403: Account locked or unverified
  </Accordion>

  <Accordion title="POST /api/auth/logout">
    **Description:** Invalidate current session token
    
    **Headers:**
    ```
    Authorization: Bearer {token}
    ```
    
    **Response (200 OK):**
    ```json
    {
      "success": true,
      "message": "Logged out successfully"
    }
    ```
  </Accordion>
</AccordionGroup>

## Security Specifications

### Authentication Flow

<Steps>
  <Step title="User Submits Credentials">
    User provides email and password through login form
  </Step>
  
  <Step title="Server Validates Credentials">
    - Hash password using bcrypt
    - Compare with stored hash
    - Verify account status (active, verified)
  </Step>
  
  <Step title="Generate Tokens">
    - Create JWT access token (15 min expiry)
    - Create refresh token (7 day expiry)
    - Store refresh token in database
  </Step>
  
  <Step title="Return Tokens to Client">
    - Send tokens in response body
    - Client stores tokens securely
    - Access token used for API requests
  </Step>
</Steps>

### Security Best Practices

<CardGroup cols={2}>
  <Card title="Password Security" icon="lock">
    - Minimum 8 characters
    - Complexity requirements
    - Bcrypt hashing (cost 12)
    - Password history tracking
  </Card>
  
  <Card title="Token Security" icon="key">
    - JWT with RS256 signing
    - Short-lived access tokens
    - Refresh token rotation
    - Token revocation list
  </Card>
  
  <Card title="Input Validation" icon="shield-check">
    - Server-side validation
    - SQL injection prevention
    - XSS prevention
    - CSRF protection
  </Card>
  
  <Card title="API Security" icon="shield-halved">
    - Rate limiting (100 req/min)
    - CORS configuration
    - HTTPS only
    - API key authentication
  </Card>
</CardGroup>

## Performance Specifications

### Caching Strategy

<AccordionGroup>
  <Accordion title="Client-Side Caching">
    **Browser Cache:**
    - Static assets: 1 year cache
    - API responses: No-cache with ETag
    - Service worker for offline support
    
    **Local Storage:**
    - User preferences
    - Non-sensitive application state
    - Draft content
  </Accordion>
  
  <Accordion title="Server-Side Caching">
    **Redis Cache:**
    - Session data (15 minutes TTL)
    - Frequently accessed content (5 minutes TTL)
    - API rate limit counters
    - Database query results
    
    **CDN Caching:**
    - Static assets (images, CSS, JS)
    - Public content pages
    - Cache invalidation on updates
  </Accordion>
</AccordionGroup>

### Database Optimization

<Info>
  Proper indexing and query optimization are critical for performance.
</Info>

- **Query Optimization:** Use EXPLAIN to analyze queries
- **Indexing Strategy:** Index foreign keys and frequently queried columns
- **Connection Pooling:** Maintain 10-50 connections based on load
- **Read Replicas:** Separate read and write operations
- **Partitioning:** Partition large tables by date or category

### Logging Strategy

<Warning>
  Never log sensitive information such as passwords, tokens, or personal data.
</Warning>

**Log Levels:**
- **ERROR:** Application errors requiring immediate attention
- **WARN:** Potential issues that should be investigated
- **INFO:** General informational messages
- **DEBUG:** Detailed information for debugging (dev/staging only)

**Log Structure:**
```json
{
  "timestamp": "2026-10-15T10:30:00.000Z",
  "level": "INFO",

  "message": "User logged in successfully",
  "metadata": {
    "ip": "192.168.1.1",

}
```

## Code Standards

### Naming Conventions

<AccordionGroup>
  <Accordion title="Files and Directories">
    - Use kebab-case for file names: `user-service.js`
    - Use PascalCase for component files: `UserProfile.jsx`
    - Group related files in directories
    - Use index files for clean imports
  </Accordion>
  
  <Accordion title="Variables and Functions">
    - Use camelCase for variables: `userName`
    - Use camelCase for functions: `getUserById()`
    - Use PascalCase for classes: `UserService`
    - Use UPPER_SNAKE_CASE for constants: `MAX_RETRIES`
  </Accordion>
  
  <Accordion title="Database Objects">
    - Use snake_case for table names: `user_profiles`
    - Use snake_case for column names: `created_at`
    - Use singular for entity tables: `user`, not `users`
    - Use descriptive names, avoid abbreviations
  </Accordion>
</AccordionGroup>
